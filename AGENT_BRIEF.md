## What this project is

Brand name: **OutageRadar**. Domain: **liveoutageradar.com** (the domain has "live" in front; the brand name does not). Logo: a green military-radar emblem with fixed dots for tracked services, a sweeping line, and an amber LIVE tag.

OutageRadar is one website built around a live **AI status board**: a page showing whether major AI services (Claude, ChatGPT, Gemini and others) are up, degraded or down, updated automatically every few minutes. Around it sit the owner's stack page and about page. There is no blog and no guides; the site grows through the board and the pages it generates automatically.

Full plan: the "OutageRadar - AI Status Board Brief" shared by the owner.

## Ground rules (non-negotiable)

1. **No predictions.** No signals, picks, forecasts, odds analysis, or performance claims anywhere. Never show or imply the owner's trading P&L.
2. **No calculators.** The site never computes prices, fees, odds, or returns. Established tools do the math; we link to them.
3. **Never invent facts.** Do not write prices, payouts, credit amounts, or promo terms from memory. Link to the vendor's official page instead. If unsure, leave a visible placeholder and flag it.
4. **Owner approves first-person content.** The owner's "My take" notes and about-page story are written in his voice. Don't change their substance without his approval, and never add new claims about his experience.
5. **"Last checked" date** on every page that mentions a tool or offer.
6. **Affiliate disclosure** on every page with affiliate links (the site footer covers this; keep it).
7. **Honest labels.** "Sponsored" only on placements someone actually paid for. No "verified" badges.
8. **Trading links** (brokers, prediction markets) need a visible risk note on the page: trading involves risk, including losing money. Follow each platform's own promotion rules.
9. **No sportsbook affiliates.**
10. **Only cover tools the owner has used or tested.** Don't add tools to the directory on your own.

## Editing pages — important

All HTML pages are generated by `build.py`. **Edit the text in build.py, then run `python3 build.py`.** Editing an .html file directly will be overwritten the next time build.py runs.

- `DOMAIN` at the top of build.py sets the canonical URLs and sitemap. Currently `https://liveoutageradar.com`.
- `CHECKED` sets the "Last checked" date.
- The tool list for the stack page is the `TOOLS` list in build.py.
- New pages: add a `page(...)` call in build.py, add the page to `urls` for the sitemap, and add it to `NAV` only if the owner wants it in the main menu.
- Commit the generated .html files along with build.py. The host serves the HTML directly; there is no build step on the server.

## Operations and alerts (run it like one of the owner's bots)

Goal: the site runs itself, and the owner hears about problems in Discord instead of checking. Everything here must run on free tiers.

**Alert channel**
- A dedicated Discord channel, separate from the owner's trading-bot alerts, fed by a Discord webhook.
- The webhook URL is a secret. Store it only in the secret settings of wherever the job runs (for example GitHub Actions secrets). Never put it in the repo, in logs, or in commit messages.
- Messages are plain English and include: what happened, which service, the time in UTC, and a link.
- Rate-limit all alerts. One alert when an incident starts and one when it recovers, with a cool-down so a flapping service can't spam the channel. A failure to send an alert must never crash the checker.

**Alert types**
1. **Major outage:** a tracked service goes down, or stays degraded for several checks in a row. Say whether the official feed and our own check agree.
2. **Feed broken:** a feed errors or returns an unexpected format for several checks in a row. Name the service.
3. **Checker heartbeat:** if the checker has not completed a successful run within a set window (start with 30 minutes), alert. The checker cannot report its own death, so this must come from outside it, such as a free dead-man's-switch service or a second scheduled job.
4. **Site down or stale:** an external free uptime monitor watches liveoutageradar.com and the status data file, and alerts if the site is unreachable or the data is older than the set window.
5. **Weekly link check:** a scheduled job opens every outbound link (affiliate links and official status pages). Post to Discord only if something is broken, and name the page and link.
6. **Deploy notice:** a short Discord message when a deploy succeeds or fails, if the host supports it for free.
7. **Weekly digest (later):** a Sunday summary of incidents, visitors and affiliate clicks, once analytics exist.
8. **Auto-posting (phase 4):** a Bluesky post when a major outage is confirmed. Factual wording and a link only, a daily post cap, and no exaggeration. The Bluesky app password is a secret.

**Rules**
- If a check or feed fails, the board shows "unknown" with the last good timestamp, never "operational".
- No paid monitoring or alert service. Confirm each service's current free-tier limits from its official docs before choosing it, and tell the owner if anything could ever bill him.
- Never print secrets in logs or error messages.

## Analytics and private dashboard

Goal: one private page where the owner can see how the site is doing, like a founder dashboard. Free tiers only.

**Phase A (at launch):** install privacy-friendly analytics, cookieless if possible. Before choosing one, verify from its official terms that the free plan allows a monetized (ads and affiliate) site, and tell the owner if anything could cost money.

**Phase B (after the status board works):** a custom private dashboard page showing:
- Human pageviews and unique visitors, with bots filtered out and shown separately
- A day-by-day chart in UTC, with any estimate for "today" clearly labeled as an estimate
- Top pages, referrers (search, direct, social, other) and countries
- Outbound affiliate clicks per link, and badge loads
- Crawler visits (Googlebot, AI crawlers) and which pages they fetch
- Outages from the status board overlaid on the traffic chart, so spikes can be tied to incidents

**Honesty rules**
- Counts must be conservative. Filter known bots and datacenter-style patterns, show the raw number separately, and flag suspicious patterns such as many hits seconds apart from one country with no referrer. Do not inflate numbers; the owner makes real decisions from this page.
- Affiliate clicks are clicks, not earnings. Never label them as income.

**Protection and privacy**
- The dashboard is private and noindex, and protected by real access control, not just a secret key in the URL. Never put keys or tokens in links.
- Store and show country-level data only. No IP addresses.
- Update the privacy page to match what is collected, and add the cookie consent banner for EU and UK visitors before ads go live.

**Discord:** a daily or weekly digest of the key numbers, plus an alert on a large traffic spike.

**Cost:** verify current free-tier limits (especially write quotas) from official docs. If the design needs a paid plan, stop and ask the owner.
